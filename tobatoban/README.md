## 画面と遊びの流れ（v6）

1. **ログイン前**：大きな3択「ログイン」「新しくアカウントを作る」「ログインせずに遊ぶ」。ID・パスワードは押したあとに開く入力欄で。左下の歯車＝設定、LINEの注意文、「セーブデータはサーバーに保存されます」
2. **ホーム**（ログイン後もゲストも同じ）：中央に次に出動する4体（3D・台座つき・名前／Lv／あなた・AI）、左に「編成」「ガチャ」「フレンド」、上にプレイヤー名／ID・セーブ・アカウント・チケット、右下にステージ欄と黄色い「出動」。ステージを選んだだけでは始まらない
3. **編成**：色付きのカード（顔と上半身・左下にLvとEXPバー・右にS〜Dランク）を横スワイプ。上で「どの枠（P1〜P4）に入れるか」と並べ替え（レベル順／ランク順／ちから順／最近使った順）、持ち物（アイテム2つ）
4. **キャラ詳細**：左に名前・ランク・役割・Lv・区間EXP（あと○EXP）・短い説明、中央に大きな3D（左右ドラッグで回転）、右に HP・ちから・ようりょく・まもり と A・X・Y・必殺の要点（くわしくは「ⓘ」）。右上の装備スロット1・2から12種を選ぶ（差分を右の能力に表示）。下の「このキャラを選ぶ」で枠へ
5. **ステージ選択**：6ステージの大きなカードを横スワイプ。未解放は鍵。選ぶとホームへ戻る
6. **協力プレイ**：フレンド一覧の「招待」（部屋は自動で用意）か、フレンド画面の「合言葉で協力プレイ」→ ホームの4枠に参加者が入る（足りない分はAI）。出動はホストだけ
7. **戦闘**：北千住 → 常磐線 → 居酒屋通り → ヨシノシン → （秋葉原へ進む・徒歩演出）→ 秋葉原駅ホーム → 駅前広場
8. **フレンド**（ホーム左の「フレンド」。公開ページでログイン中だけ）：自分のフレンドコード（例 `K7Q4-2MPX`）をコピー／「招待リンクを送る」→ 相手がコードを入れるかリンクを開いてログイン →「申請」→ こちらが「承認」。一覧に オンライン／ルーム○○で募集中／プレイ中／最終○分前 が出て、募集中のフレンドには「参加」で合言葉なしに入れる。ルームを作っている間はオンラインのフレンドへ「招待」を送れ、相手のホームに通知（参加・×）が出る

## フレンド（なぜログインIDをフレンドIDにしないか）

- ログインIDは 1〜10000 の連番で、**パスワードと組のログイン情報**です。フレンドIDに使うと、IDを人に見せることになり、番号を順に試すだけで知らない人へ申請を送れてしまいます
- そこで、アカウントごとに **ランダムな8文字のフレンドコード**（`0 O 1 I L` のような見まちがえる字は使わない・約8.5×10¹¹通り）を別に作ります。コードを知っている人だけが申請でき、一覧から探すことはできません。教えてもログインはできません
- 申請は「申請（req）→ 相手の承認（ok）」の2段階。相手からも申請が来ていれば、申請した時点でフレンドになります。フレンドと申請は合わせて50人まで。どちらからでも解除できます
- 状態（なまえ・先頭キャラ・最後に見えた時刻・募集中のルーム）は**フレンドだけが読めます**。2分ごとと、状態が変わったときに知らせ、5分更新がなければオフライン扱い。ログアウトで即オフライン
- 一覧は読み込みだけ（常時接続はしない）。フレンド画面を開いている間は20秒ごと（相手の状態も読む）、ほかの画面では90秒ごと（申請と招待だけ）、戦闘中は読みません。招待は5分有効
- Firestore の無料枠（1日に読み取り5万・書き込み2万）の目安：1人が1時間開いていると、書き込み約30回、読み取りは「フレンド数×40回」ほど（ホームにいる間）。フレンド画面を開きっぱなしにすると増えます
- **使うには `firestore.rules` を Firebase コンソール（Firestore → ルール）に貼りつけて公開する必要があります。** 古いルールのままだと、フレンド画面に「サーバーの設定を確認してください」と出ます（ログイン・セーブは今まで通り使えます）
- ログインしていないとき・claude.ai の中（端末内セーブ）では使えません

## v7：通信とフレンド招待（P1）

**直したこと**
- 接続前と接続後で、待つ時間を分けました。以前は、部屋に入る処理が返った瞬間から6秒の無応答判定が始まっていました。WebRTCの相手探し（Nostr）と接続は10秒以上かかることがあり、つながる前に「6秒とだえた」で切れることがありました（コードから考えられる原因の一つで、実機のログではまだ確認していません）
  - 接続前：ホストのロビー情報が届くまで30秒待ちます（`NET.connectTimeout`。出発点の値で、実測で調整します）
  - 接続後：6秒とだえると「再接続中」、25秒続くと切断。画面を裏にしていた時間は数えません
  - ホスト側：参加者が6秒とだえるとAIが一時的に代わり、通信が戻れば操作も戻ります。30秒で枠を外します
- 相手を見つけたらすぐ、ホストはロビー情報を、参加者はあいさつを送ります（1秒ごとの定期送信を待たない）
- 状態を「接続準備中／接続確立中／ロビー参加済み／戦闘中／再接続中／切断」に分けて表示します。失敗の理由も分けて出します（ホストが見つからない・つながらない・直接つながらない＝TURNが必要な可能性・とだえた・ホストが閉じた・満員・開始済み・版違い）
- 送信の失敗と、同梱Trysteroの `onJoinError` を開発用ログに残します。**`?debug=net` を付けて開くと、画面の左下に接続の経過が出ます**
- 部屋を作る・入るボタンの連打で、セッションが重ならないようにしました。合言葉は6けたにしました（ほかの人の部屋と重なりにくくするため）

**フレンドから直接さそう**
- ホームの「協力プレイ」ボタンをなくしました。フレンド一覧の各行の「招待」を押すと、部屋を裏で自動で用意してから招待を送ります。自分の部屋がすでにあれば、それをそのまま使います
- 招待された側には、ホームに通知（参加・×・残り時間）が出て、一覧にも「招待が届いています」と「参加」が出ます。合言葉を入れる必要はありません。参加する前に、期限（5分）が切れていないか、部屋がまだ開いているか、戦闘中でないかを確かめ、だめなときは理由を出します
- ホストの部屋の「リンク」から参加リンク（`?join=合言葉`）を送れます。ログインしなくても参加できます。フレンド申請のリンク（`?friend=コード`）とは別のものです
- フレンドの名前やアイコンを押すと、プロフィールが開きます（名前・先頭キャラ・Lv・状態・フレンドになった日）
- フレンド以外の人と遊ぶときは、フレンド画面の「合言葉で協力プレイ」から部屋を作るか入ります
- Firestoreのルールは**変えていません**（招待は今の `inv { by, room, t }` だけを部分更新します）

**確認できていないこと**
- 別の端末・別の回線（Wi-Fiとモバイル回線など）でのWebRTC接続は、この環境では試せていません。確認できたのは、同じブラウザ内の通信（BroadcastChannel）とメモリ上の通信（遅延・重複・欠落あり）での動きだけです
- 回線によっては直接の通信ができず、TURNサーバーが必要になることがあります。`NETLIB.ICE.turn`（固定のTURN）か `NETLIB.ICE.url`（短期の認証情報を返すURL）で設定できるようにしましたが、TURNサーバー自体はまだ用意していません（下の「TURNを使うとき」）

**TURNを使うとき（未設定）**
- 長く使える秘密情報（ユーザー名とパスワード）を公開HTMLに書かないでください
- 短期の認証情報を発行するサービスを使います（例：Cloudflare Realtime TURN、Metered、Twilio Network Traversal）。サービスのAPIキーはサーバー側（Cloudflare Workers や Firebase Functions など）に置き、そこから `{"iceServers":[{"urls":"turn:…","username":"…","credential":"…"}]}` を返すURLを作ります。そのURLを `src/net.js` の `ICE.url` に書くと、部屋を作る・入るたびに取得して使います
- Firebase Functions を使うには Blaze（従量課金）プランが必要です

## v8 第1優先：フレンド招待・参加の通信

- **症状**：招待→参加で、参加者が誰もいないロビーへ移り、待つと切断。原因は2つ。①参加者は「部屋の準備ができた」時点で空のロビーを表示していた（ホストが枠を確定したかを待っていない） ②ホストが見つからない・直接つながらない場合も、その空のロビーで待たされていた
- **直した流れ**：参加を押す→「部屋に入っています」の画面（部屋に入る準備→ホストを探す→ホストとつなぐ→参加の受け付け）→ホストが枠を確定して確認応答（`wel`）を返したときだけ参加完了とロビー表示。確定までは0.6秒ごとにあいさつを再送（同じ peer ID は同じ枠のまま＝二重登録しない）。ホストは受け付けと同時に一覧を全員へ送るので、両端末で同じ人数がそろう
- **理由の区別**：ホストが見つからない（`no_peer`。片方が古い版の可能性も表示）／見つかったが通信がつながらない（`no_lobby`・`p2p_failed`）／受け付けが返らない（`no_ack`）／満員（`full`）／開始済み（`started`）／版違い（`version`）／招待の期限切れ。失敗したら部屋を片付けて、同じ合言葉ですぐ入り直せる。「やめる」ボタンもある
- **画面の切り替え中も通信を続ける**：協力のセッションはどの画面でも毎フレーム更新し、画面が裏に回って描画が止まっても0.5秒ごとに送受信を続ける
- **相手探し**：Nostr の中継を5→10か所に（落ちている中継が混じっても見つかるように）。通信の版は `tb8`（古い版とは同じ部屋に入れない＝両方の再読み込みが必要）
- **TURN（中継サーバー）**：今は未設定。学校・会社のWi-Fi、モバイル回線どうしなどで直接つながらない場合に必要。設定方法：TURNサービス（例：Metered・Cloudflare Calls など）の「iceServers を返すURL」を `?turn=URL` で一度開く（端末に保存される）。公開ファイルに長期の秘密は書かない
- **確認**：通信テスト（遅延・重複・欠落ありで2人→3人→4人・5人目は満員・再送で二重登録しない）、同じブラウザの4タブでの入室確認（`tools/join-check.py`）、フレンド招待→参加（Firebase エミュレーター＋同じブラウザ）。**別の実機どうしのWebRTC通信は未確認**（この環境ではできない）。実機では `?debug=net` で手順ごとのログが見られる
- 公開前に `src/build.py` が構文を確かめる（壊れたまま公開しない）

## セーブと公平性（正直な注意）

- **このゲームのセーブは改ざんを防げません。** 端末内版（localStorage）は持ち主がブラウザで書き換えられますし、Firebase版も「本人だけが自分のセーブを読み書きできる」ルールで、セーブの中身（所持・EXP・チケット・勝利数・ガチャ結果）はブラウザが計算して丸ごと書き込みます。信頼できるサーバーで報酬や抽選を確定する仕組みはありません。友だちどうしのローカル試遊として扱ってください
