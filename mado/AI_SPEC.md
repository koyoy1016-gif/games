# 窓際社員ギリギリゲーム — AI改善用 仕様書

このファイルは、AI（Claude など）がこのゲームを**自分で検証しながら品質を上げ続ける**ための仕様書です。
人が「〇〇を足して」と頼むときも、このファイルを一緒に渡すと話が早くなります。

---

## 1. ゲームの核（変えてはいけないこと）

- おじさんを机（台車）ごと滑らせ、**窓（x=50m）の手前ギリギリ**で止めるゲーム。
- 操作は**パチンコ式**：画面を後ろへドラッグ → 離すと**反対方向**へ発射。
- 力の目安：**60%で約48m**（窓の近く）。100%だと窓を割って外に落ちる。
- 1日1発。止まった位置で日報（結果カード）が出て、翌日は**新しいランダム配置**。
- 窓を割ると外に落ちて「再出社」＋始末書。**失敗も笑える演出**にする。
- どの配置も**必ずクリア可能**で、**複雑すぎない**こと（自動検査で保証）。

## 2. ファイル構成

```
mado/
  index.html            ← 配信される1ファイル（ビルド成果物。直接編集しない）
  src/
    head.html           ← HTML と CSS（UI）
    three.min.js        ← three.js r149（触らない）
    core.js             ← 物理・ステージ生成・クリア判定（three.js 非依存）
    game.js             ← 描画・入力・演出・画面遷移
    build.py            ← src/ を結合して index.html を作る
  tools/check-stages.mjs← ステージ自動検査
  AI_SPEC.md            ← この仕様書
```

**編集の流れ（必ず守る）**

1. `src/` を編集
2. `python3 mado/src/build.py` で `index.html` を再生成
3. `node mado/tools/check-stages.mjs` が ✅ になることを確認
4. 可能ならブラウザで実際に動かし、スクリーンショットで見た目を確認（§6）

## 3. 物理とパラメータ（`src/core.js` の `C`）

| 名前 | 値 | 意味 |
|---|---|---|
| `MAXD`, `CURVE` | 67, 0.65 | 飛距離 = MAXD × 力^CURVE。60%≈48m。CURVE<1 なので中盤の力で細かく調整できる |
| `DECEL` | 5 | 床の減速 [m/s²] |
| `REST` | 0.55 | 壁・障害物での跳ね返り係数 |
| `H` | 1/120 | 固定タイムステップ。**ゲーム本体と判定で同じ値を使う**ので、判定で成功した手はゲームでも必ず成功する |
| `ZONE` | 48 | 前端がここ以上で「窓際」成功 |
| `DRAG_FULL` | 0.55 | 画面短辺×この比率のドラッグで力100% |

床ゾーン：`wax`（摩擦0.45＝よく滑る）、`mat`（摩擦2.2＝止まりやすい）。
床ワックス（その日全体）：重い0.94 / 普通1 / よく滑る1.06（飛距離に掛かる）。

## 4. ランダムステージ

- `MadoCore.build(seed, diff)` が、生成 → 総当たり判定 → 条件を満たすまで作り直し、を行う。
- 判定 `evaluate()`：角度（−84°〜84°、4°刻み）×力（20〜100%、1.5%刻み）を全部シミュレーションし、窓際に止まる割合 `rate` を出す。障害物なしの部屋で約2.1%。
- 難易度ルール `DIFF_RULE`：

| 難易度 | 出現率 | 条件 |
|---|---|---|
| easy | 30% | rate≥0.9%、まっすぐ届く手が4つ以上 |
| normal | 45% | 0.45%≤rate≤1.4% |
| hard | 25% | 0.3%≤rate≤0.7%、成功手7つ以上（壁バウンド等で必ずクリア可） |

- ★（1〜5）は rate から自動計算して画面に表示。
- テーマ（`THEMES`）：フリーアドレス日／在宅勤務デー／整理整頓／いつものフロア／会議ラッシュ／ワックスがけの日／引っ越し前日／模様替え中／パーテーション迷路。
- 障害物の種類：`island`（島デスク・同僚が座る）`pillar` `plant` `copier` `meeting` `boxes` `shelf` `partition`。
- 翌日のステージは Web Worker で**先読み**するので、生成中に画面が固まらない。

**新しい障害物を足すとき**：`core.js` の `SIZES` と `THEMES[].kinds` に追加 → `game.js` の `buildObstacle()` に見た目を追加。当たり判定は常に軸平行の箱（AABB）。

## 5. ランダム演出（`src/game.js` の `EVENTS`）

毎日、各イベントが確率 `p` で独立に起きる（1つも起きなければ1つ選ぶ）。

| id | 確率 | 内容 |
|---|---|---|
| senkyaku | 45% | 窓から落ちた先輩社員が植え込みに1〜5人（寝転ぶ・机ごと座って仕事中・手を振る）。着地すると話しかけてくる。上に落ちると「ムギュッ」 |
| drill | 20% | 防災訓練。ビル下にレスキューマット → 落ちると「ボヨーン！」とバウンド |
| gondola | 25% | 窓拭きゴンドラが外を上下。条件が合うと落ちたおじさんをキャッチ |
| pigeons | 40% | 窓台の鳩。台車が近づく／窓が割れると飛び立つ |
| crowd | 30% | ビル下の野次馬。窓が割れるとスマホで撮影（フラッシュ） |
| blimp | 12% | 空に飛行船（横断幕の文言もランダム） |
| papers | 35% | 高速で滑ると書類が舞う |
| cat | 15% | 窓際に猫。近づくと逃げる |

それ以外に毎日ランダム：**天気**（晴れ／夕焼け／雨／残業の夜）、**上司**（課長／部長／社長でセリフ・歩く速さ・見た目が違う）、
**社内放送**、**同僚の反応**（ぶつかる・通過・窓際成功で拍手）、**日報コメント**、**再出社ルート**と**言い訳**。

**新しい演出を足すとき**：`EVENTS` に `{id, p, setup(fx){...}}` を追加するだけ。
- 3Dオブジェクトは `fxG` に入れる（翌日に自動で片付く）。
- 毎フレーム動かすなら `npc(P, (dt,t)=>{...})` か `updateFx()` に追記。
- 窓割れ時は `crash()`、着地時は `onLand()`、窓際成功時は `finishSlide()` にフック。
- `fx.labels` に名前を入れるとデバッグ表示に出る。`fx.notices` に入れると社内放送で流れる。

## 6. 検証方法（AIが自分で確認する手順）

### URLパラメータ（デバッグ用）
- `?debug=1` … 画面左下に seed／難易度／rate／**模範解答の角度と力**／今日の演出を表示。ミニマップに解答方向（緑の点線）
- `?seed=12345&diff=hard` … 同じフロアを再現
- `?ev=drill,gondola,senkyaku` … 演出を強制。`?weather=rain` `?boss=shacho` も可
- `?fx` … 1日目から演出をランダムに出す（通常1日目はチュートリアル寄りで鳩のみ）

### 自動操作フック
ブラウザのコンソール（Playwright の `page.evaluate`）から：
```js
__mado.st.stage.sol          // 模範解答 {a:角度, p:力%}
__mado.launchShot(16, .59)   // 角度16°・力59%で発射
__mado.st.mode               // ready / aiming / sliding / chill / boss / falling / landed / commute / walkin / result
__mado.nextDay()             // 翌日へ
```

### ヘッドレスブラウザでの確認（推奨手順）
1. Playwright + Chromium（`--use-angle=swiftshader`）で `index.html?seed=...&debug=1` を開く
2. `launchShot(sol.a, sol.p/100)` → `mode` が `chill` → `result` になることを確認（窓際成功）
3. 力1.0で窓を割る → `falling` → `landed` → `commute` → `walkin` → `ready` を確認
4. 各段階でスクリーンショットを撮り、文字の重なり・はみ出し・真っ黒な画面がないか目視
5. コンソールエラーが0件であること
※ ヘッドレスは描画が遅く、ゲーム内時間がゆっくり進む。待ち時間は長めに（60秒程度）。

## 7. 品質チェックリスト（変更のたびに）

- [ ] `check-stages.mjs` が ✅（全ステージがクリア可能、生成は最大3秒以内）
- [ ] 力60%で44〜52m届く
- [ ] スマホ縦（390×780）と横（1024×640）でHUD・吹き出し・日報が重ならない
- [ ] 窓際成功 / 失敗（上司） / 窓割れ の3ルートが最後まで進む
- [ ] コンソールエラー0件
- [ ] `prefers-reduced-motion` で揺れ・紙吹雪が止まる
- [ ] 同じ日に同じ演出が続きすぎない（確率の合計が高すぎないか）

## 8. 改善アイデア（バックログ）

優先度順。AIはここから1つ選び、§7を満たして実装 → この表を更新する。

1. **効果音**（WebAudioで合成：滑走音、ドン、ガシャーン、ボヨーン、上司の怒鳴り）— ミュートボタン付き
2. **ゴースト**：前回の自分の軌跡を薄く表示して微調整しやすく
3. **週間モード**：月〜金の5日間の合計スコアと「今週の称号」
4. **フロア共有**：日報の「フロアNo.」から `?seed=` 付きURLをコピーして友達と同じ配置で勝負
5. **動く障害物**（お掃除ロボット、台車を押す同僚）— 判定にも同じ動きを入れてクリア保証を維持すること
6. **称号コレクション**（「鳩と目が合った」「社長に怒られた」「ゴンドラで救出」など演出の達成で解除）
7. **上司の巡回**：上司がフロアを歩いていて、軌道上で当たるとその場で説教
8. **季節イベント**（桜・梅雨・夏の打ち水・年末大掃除）を日付で切り替え
9. 低スペック端末向けに影・ピクセル比を自動で下げる

## 9. やってはいけないこと

- `index.html` を直接編集する（次のビルドで消える）
- 判定と本体で別々の物理を書く（クリア保証が崩れる。必ず `MadoCore.step` を共有）
- 外部の画像・音声ファイルを読み込む（1ファイル配信のため、すべてコードで生成する）
- 実在の人物・企業ロゴ・既存キャラクターを登場させる
